# VM 分析定义（.scr 字节码）

本文件是 `opcodelist.py` / `disassembler.py` / `assembler.py` 的**唯一真值源**：
任何指令长度、操作数布局的修改都必须先改这里，再改 `opcodelist.py` 并重跑逐字节校验。

## 0. 结论摘要

| 项目 | 结论 |
|---|---|
| 引擎 | Will Co.（GARbro: `WARC`） |
| VM 函数 | `sub_405160`（0x00405160 - 0x004081E8） |
| 指令流 | 1 字节 opcode + 小端操作数，无对齐 |
| 脚本基址 | `dword_467F84`，指令指针 `dword_467F88` |
| 文本 | 内联 CP932、NUL 结尾；引擎换行是两个字节 `5C 6E`（字面 `\n`） |
| 跳转 | 0x01 相对(指令末)、0x06 绝对(相对脚本起点) |
| 校验 | 122 个脚本、26,111 条指令零残留；1,852 个跳转目标全部落在指令边界 |

## 1. 证据来源

- `exe/Chijyoku.exe`（Will Co. 引擎，2004，430,080 B，ImageBase 0x400000）
- IDA 9.1 导出：`exe/Chijyoku.exe.pseudocode.c`、`exe/Chijyoku.exe.disasm.asm`、`exe/Chijyoku.exe.i64`
- 样本：`scr/SCR/*.scr`（从 `Rio.arc` 解包，ROR2 解密后的 122 个脚本）
- 生成工具：`opcodelist.py`（本表）、`disassembler.py`、`assembler.py`

## 2. VM 类型与执行模型

- **字节码解释器**，非寄存器机/非栈式表达式机：每条指令由 1 字节 opcode 与紧随的定长/变长操作数组成。
- `sub_405160` 是主解释循环：`while` 取 `*(BYTE*)dword_467F88` 进 `switch`，每个 case 负责推进 `dword_467F88`。
- 少数指令不直接推进指针，而是跳到共享出口（`LABEL_518` 等）由公共代码推进；本表长度取自各 case 的净推进量。
- 调用模型：0x09 把当前偏移压入 `dword_469A98` 栈并加载新脚本；0x0A 弹栈恢复。
- 变量模型：`word_5439C0[]` 为 16 位变量数组；0x03 做算术，0x0C 比较。
- 条件链：连续的 0x01 记录逐条判断，全真才继续；任一为假跳到各自 rel32 目标。

## 3. 指令边界规则

- 脚本没有文件头：偏移 0 即第一条指令。
- 指令之间无对齐填充；字符串长度为字节数 + NUL。
- 0xFF 为结束标记，位于脚本最后一个字节。
- 0x00 出现在无条件跳转之后的空位，按 1 字节处理（不可达）。
- 跳转目标必须落在指令起始地址；`disassembler.py` 会校验，不满足即报错。

## 4. 文本与符号存储

- 文本**内联**在指令中（`TEXT`/`SAY`/`SELECT` 选项），不是独立字符串池。
- 编码为 CP932（日文）；改中文时可用 GBK 重编码（见 `GBK.py`）。
- 引擎换行 = 字节序列 `5C 6E`（ASCII 反斜杠 + n）；asm 中写作 `\n`，字面反斜杠写作 `\\`。
- 无法解码的字节在 asm 中用 `{{XX}}` 占位，汇编器原样还原。
- 文本变长会移动后续指令，因此 0x01/0x06 的目标必须用标签重定位；`assembler.py` 已实现。

## 5. 跳转与标签策略

- 0x01：目标 = 指令地址 + 11 + rel32（相对**指令末**）。
- 0x06：目标 = u32（相对**脚本起点**的绝对偏移）。
- asm 用 `loc_XXXXXXXX` 标签；汇编器两遍布局，先定标签地址再回填。
- 未发现其它代码指针：122 个样本的全部 0x01/0x06 目标都能落到指令边界；其余字段按普通数值处理，
  因此文本改长后只需要重定位这两类目标（0x41 的 u16 是语音序号，不是指针）。

## 8. 关键 opcode 的运行时行为（对写补丁有用）

### 文本显示

`0x41 TEXT` / `0x42 SAY` 把文本交给 `sub_411880` 入消息队列；`SAY` 先设置人名再入队。
两者都不会主动停止语音。

### 语音

`0x23 VOICE` 在播放前调用 `sub_42AD70(sound_mgr, 1)` 停止语音槽 10（`eax=0, edx=1` → 索引 `eax+10`）。
点击推进文本时，消息处理函数 `sub_402D60` / `sub_403F80` / `sub_404290` 也会调用同一函数停止槽 10，
这就是“翻页打断语音”的原因；`patch_voice.py` 改的正是这些调用点（见 `EXE_PATCHES.md`）。

### 选择

`0x02 SELECT` 的每条选项：`u16` + 文本 + 类型字节 + 负载。
类型 7 的负载是脚本名（选中后跳转），类型 3/6 是条件/延时负载。

### 字体/编码

GDI 字体由 `sub_42C660` 创建，`lfCharSet` 决定字节解释代码页（0x80=Shift-JIS，0x86=GB2312）。

## 9. 未确认项与风险

- 表中标“仅长度/边界确认”的 opcode 语义未定，但长度经 122 个样本全量验证。
- 0x02 选择块只确认了类型 3/6/7，其它类型未在样本出现。
- 0x00 按 1 字节填充处理；若未来版本把它当有效指令，需要重新确认。
- 跨版本复用时必须先验证：0x01 的 11 字节记录、0x06 的绝对偏移、字符串位置是否仍一致。

## 10. 复现与校验

```
python disassembler.py scr/SCR -o asm
python assembler.py asm -o rebuild
```
对 122 个脚本执行上述流程，`rebuild` 与 `scr/SCR` 逐字节一致（SHA-256 全等），
且反汇编阶段会校验全部跳转目标落在指令边界。
