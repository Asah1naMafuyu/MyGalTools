# VM Analysis — MIBOUJIN（Tanaka 系 SCB 脚本）

对象：`MIBOUJIN.EXE`（Borland C++ Builder，ImageBase 0x400000）与
`MIBOUJIN.SCB` 解包出的 100 个脚本。

## 1. 结论摘要

- 脚本是**长度前缀的命令流**，不是传统堆栈 VM：
  `[u8 length][u8 command][operands...]`，`length` 含自身与命令字节。
- 脚本以 `0x00` 结束；结束符之后可能有 1–7 字节对齐/残留数据，必须原样保留。
- 文本为 CP932，直接内嵌在 `TEXT`/`SPEAKER`/`TITLE`/`SCENE`/`ENDING` 记录里，
  末尾 `0x00`。文本中的 `/c`、`/p` 是游戏内换行/等待标记，属于文本内容，不是 opcode。
- 样本中出现 15 种命令，已全部覆盖；没有发现跳转指令或指向块外的绝对偏移
  （全脚本扫描：没有任何 dword 等于块偏移）。
- 100 个脚本反汇编→汇编后 SHA-256 全部一致（零突变）。
- **脚本内的块引用全部按“名字”解析**（`LABEL` 的 `0x21/0x40` 前缀），
  而**回想界面还有一份 EXE 内置的 13 条章节名**。改章节名必须同步 EXE，
  否则回想整页不可点（详见 §6，2026-11-13 实测确认）。

## 2. 证据链

| 事实 | 证据 |
|---|---|
| SCB 容器结构 | `SCB_FORMAT.md`；加载器 `sub_409BCC`、取块 `sub_40A2A0` |
| 记录格式 = 长度+命令+参数 | `MIBOUJIN.EXE` 的脚本编译器 `sub_410D70`（按命令字符写 `*v118++ = 长度/命令/参数`） |
| 长度含自身 | 编译器写入 `*v3 = (_BYTE)v118 - (_BYTE)v3`，即整条记录长度 |
| `0x00` 结束 | 解释器 `sub_40F3F8`：`mov al,[edx]; test eax,eax; jz ...` 后调用结束处理 |
| 文本为 CP932 | 全样本 `TEXT` 负载按 CP932 解码可读；不可还原字节用 `{{XX}}` |
| 无压缩/加密 | 加载器只 `FileSeek`+`ReadFile`；块熵 2.67–5.93 |
| 名字→块 的解析 | `0x40A544` 按名字在字符串表线性查找，命中后 `FileSeek`+`ReadFile` 载入该块 |
| 回想可用性判定 | `0x406F58` → `0x416FBC` → `0x416F64`（字符串表按名查索引）→ `obj+0xA654[index]` 解锁位 |

长度前缀的实测：100 个脚本从头解析到 `0x00`，全部记录长度合法且不越界；
尾部残留 ≤7 字节，作为 `.byte` 数据原样保留。

## 3. 指令集

`length` 为整条指令字节数，`operands` 长度 = `length - 2`。

| 命令 | 助记符 | 参数 | 说明 |
|---|---|---|---|
| 0x09 | `TEXT` | CP932 文本 + `00` | 正文/对白 |
| 0x21 | `LABEL` | u8 ×2 + 文本 + `00` | 标签/块引用，前缀语义见 §3.1 |
| 0x23 | `CHAR` | char[4] + u16 ×3 | 角色定义（YUKI、JK_A…） |
| 0x24 | `ANGLE` | u16 ×2 + 3×C 字符串 | 多角度/多视点（マルチアングル） |
| 0x25 | `SPEAKER` | 文本 + `00` | 说话人名牌（【由希】） |
| 0x2E | `IF` | 子码见下 | 条件/控制 |
| 0x2F | `TITLE` | 文本 + `00` | 场景/分支标题 |
| 0x3A | `SCENE` | 文本 + `00` | 场景入口（按名字被 `LABEL` 跳转） |
| 0x3E | `ENDING` | 文本 + `00` | 结局标题 |
| 0x40 | `RET` | u8 | 段结束；样本中恒 0 |
| 0x43 | `CMD43` | u8 ×2 | 全样本仅 1 条，语义未确认 |
| 0x46 | `FLAG` | 操作符 + u16 | `F-` 清标志 / `F+` 置标志 |
| 0x47 | `BG` | u16 ×3 + C 字符串 | 背景/事件资源（bg_01、EV_01A_1） |
| 0x52 | `VAR` | 操作符 + u16 + u16 | `R=` 变量比较/赋值 |
| 0x57 | `SND` | 见下 | 音频 |

### 3.1 `LABEL`（0x21）前缀语义

记录布局：`[len][0x21][pre0][pre1][名字][00]`。

| pre0 | pre1 | 反汇编写法 | 语义 | 证据 |
|---|---|---|---|---|
| `0x21` | `0x40` | `LABEL 0x21, 0x40, "块名"` | **调用**：按名字解析到块，压返回地址后跳过去 | block 43 调用各章节块后仍继续执行 `VAR`/`IF_C`；`0x40AE40` 中 `pre0==0x21` 分支分配节点并登记返回位置 |
| `0x00` | `0x40` | `LABEL 0x00, 0x40, "块名"` | **跳转**：同上但不压返回 | block 0 用它跳到 `スタート`（字符串表第 43 项） |
| `0x00` | `0x00` | `LABEL 0x00, 0x00, "SCENE 名"` | **块内跳转**：跳到本块同名 `SCENE` | block 60 用它跳过序章直达 H 场景 |

- 实测：全样本 136 条 `LABEL`，其中 `pre1=0x40` 的 119 条
  （43 条 `00,40` + 76 条 `21,40`）**全部**能在字符串表里找到同名块，命中率 119/119；
  其余 17 条 `00,00` 中有 7 条与块同名、10 条是块内 `SCENE` 名。
- `0x40` 这一路在 `0x40A544` 里表现为：遍历 SCB 文件字符串表逐字节比较，
  命中就 `FileSeek`+`ReadFile` 读取该块并跳转（`sub_416E40`）；未命中则静默返回。

### 0x2E 子码

| 子码 | 反汇编写法 | 参数 |
|---|---|---|
| 0x01 + 0x46 | `IF_F <op>, <u16>` | 内嵌 `FLAG` 判断 |
| 0x01 + 0x52 | `IF_R <op>, <u16>, <u16>` | 内嵌 `VAR` 判断 |
| 0x05 / 0x06 | `IF_V <子码>, <u16>` | 带 u16 参数 |
| 其它（0x03/0x08/0x09/0x0A/0x63） | `IF_C <子码>` | 单字节码 |

### 0x57 子类型

- `SND 'M', n`：`M` + u16 音乐编号。
- `SND 'V', 'P'/'d', "se_xx", flag`：`V` + 子类型 + `00` + 资源名 + `00` + flag。
  样本中 flag 基本为 0，`se_26` 一处为 0x81，因此作为独立操作数保留。

## 4. 文本与编码

- 落盘 asm.txt 为 UTF-8；`--encoding` 只影响字符串的二进制编码。
- 反汇编默认 `cp932`，汇编默认按 asm 头部 `; encoding:`，无头部时 `gbk`
  （与用户指定 `--encoding gbk` 一致，便于中文注入）。
- 不可显示/不可还原的字节写作 `{{XX}}`；字面 `{` 写作 `\{`，`"` 写作 `\"`。
- 文本末尾 `0x00` 不写入 asm，汇编器自动补回。

## 5. 零突变验证

```
python disassembler.py MIBOUJIN.SCB_unpacked -o out_asm --encoding cp932
python assembler.py out_asm -o out_bin --encoding cp932
```

100 个脚本逐个比较 SHA-256：**100/100 一致**。

## 6. 跨文件名字契约（2026-11-13 回想 BUG 复盘）

### 6.1 现象

汉化后进入「イベント」（回想）界面：13 个条目文字正常显示，但**鼠标移上去无高亮、
点击无反应**；同一存档下「もくじ」（章节选择）完全正常。

### 6.2 判定链（EXE 侧）

| 地址 | 作用 |
|---|---|
| `0x406F58` | 回想界面逐项刷新：遍历 EXE 内置的 13 条章节名（第 2 页从第 9 条起，对应「1/2ページ」） |
| `0x416FBC(name)` | 查询该名字对应块是否解锁：找不到直接返回 0 |
| `0x416F64` | 在 SCB 字符串表（`obj+0x8BA4`，数量 `obj+0x8B74`）里按字节线性查找，命中返回索引，否则 `-1` |
| `obj+0xA654 + index` | 每个块的「已到达」标志 |
| `0x406FDA` | 查找失败 → 菜单项 `[item+0x44E] = 0`，该项禁用（所以鼠标毫无反应） |

结论：回想项能不能点，取决于「EXE 内置名字」能否在 `.table` 里查到；
与 block 44–56 的内容无关。

### 6.3 数据位置

- 13 条章节名字符串：文件偏移 `0x0A1B5A` 起（`.data`），CP932，`0x00` 结尾，
  连续存放，合计 0x1C5（453）字节。
- 指针表：13 个 dword，VA `0x4A2740`（文件 `0x0A1340`），只被 `0x406FA1` 引用。
- 这 13 条对应的 `.table` 索引：66, 68, 71, 75, 78, 79, 83, 87, 91, 93, 95, 97, 99。

### 6.4 契约

同一个章节名字符串，在下面**四处**必须逐字节相同：

1. `.table` 第 58–99 项（字符串表；游戏按名字查块用的就是它）；
2. block 43 的 `LABEL 0x21,0x40,"…"`（もくじ 菜单调用章节块）；
3. block 44–56 的 `LABEL 0x21,0x40,"…"`（回想播放列表调用章节块）；
4. EXE `0x0A1B5A` 的 13 条（回想项可用性判定）。

任一处不同步 → 名字解析失败。第 2 处不同步会坏「もくじ」，第 4 处不同步会坏「回想」。

### 6.5 复核数据

- 日文原版：`pre1=0x40` 的 119 条标签 119/119 命中 `.table` 名字。
- 只改 `.table` 58–99 的汉化版：block 44–56 的 34 条引用 **0/34** 命中；
  block 43 与 `.table` 同为中文、彼此一致 → もくじ 正常、回想全灭。
- 修复后：119/119 命中，34/34 调用可解析，`.table` 无重名。

### 6.6 修复与回归

`patch_event_names.py` 按 `.table` 索引把 EXE 的 13 条改成与 58–99 相同的字节：
优先原地替换（长度不变时 diff 最小），个别变长时整体重排并更新指针表；
已打过补丁的 EXE 再跑会直接返回（幂等）。

每次改动 58–99 的章节名后，按顺序执行：

```
python disassembler.py MIBOUJIN.SCB -o out
python assembler.py out\MIBOUJIN.asm.txt -o rt.scb --encoding cp932   # 应与原文件逐字节一致
python patch_event_names.py MIBOUJIN.EXE --scb MIBOUJIN.SCB --jp MIBOUJIN.SCB.JP
```

游戏内实测清单：もくじ 可点、回想 13 项可高亮并可进入、章节名显示为中文。

### 6.7 适用范围与限制

- 改 `.table` 44–56（回想列表显示名）**不影响**该判定；那 13 条只用于解锁条件。
- 块数量/顺序变化时索引对应关系失效；脚本会因找不到指针表或条目数不符而报错退出。
- 13 条新名字合计超过 453 字节时脚本拒绝写入（需要另找空间并改指针）。
- 只对同一版本 EXE 有效；换用语音/GBK 等补丁版 EXE 后需要用本脚本重新打一次。

## 7. 未确认项

- `0x2E` 各子码在运行时的确切语义（等待/跳转/结束）未做动态调试确认，命名 `IF_*` 为
  基于内嵌 `F`/`R` 判断的推断。
- `0x40`、`0x43` 的语义只按参数形状命名，未在游戏中验证。
- `0x21` 首字节为 0x21 时多出的前缀字节含义未确认（现按「调用/跳转 + 名字类别」解释）。
- `0x40A138` 判断首字符类别（ASCII 返回字符本身 / 双字节查表）与 `pre1=0x40`
  在样本中完全重合，二者未能区分；若以后出现 `pre1=0x40` 但以半角字符开头的标签，
  可据此判定究竟是哪个条件在起作用的。
- 未做游戏内实测的部分：分支跳转、`IF_C` 各码的等待语义、语音触发时机。
