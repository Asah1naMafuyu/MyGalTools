# VM Analysis — MIBOUJIN（Tanaka 系 SCB 脚本）

对象：`MIBOUJIN.EXE`（Borland C++ Builder，ImageBase 0x400000）与
`MIBOUJIN.SCB` 解包出的 100 个脚本。

## 1. 结论摘要

- 脚本是**长度前缀的命令流**，不是传统堆栈 VM：
  `[u8 length][u8 command][operands...]`，`length` 含自身与命令字节。
- 脚本以 `0x00` 结束；结束符之后可能有 1–7 字节对齐/残留数据，必须原样保留。
- 文本为 CP932，直接内嵌在 `TEXT`/`SPEAKER`/`TITLE`/`SCENE`/`ENDING` 记录里，
  末尾 `0x00`。文本中的 `/c`、`/p` 是游戏内换行/等待标记，属于文本内容，不是 opcode。
- 样本中出现 15 种命令，已全部覆盖；没有发现跳转指令或指向块外的绝对偏移
  （全脚本扫描：没有任何 dword 等于块偏移）。
- 100 个脚本反汇编→汇编后 SHA-256 全部一致（零突变）。

## 2. 证据链

| 事实 | 证据 |
|---|---|
| SCB 容器结构 | `SCB_FORMAT.md`；加载器 `sub_409BCC`、取块 `sub_40A2A0` |
| 记录格式 = 长度+命令+参数 | `MIBOUJIN.EXE` 的脚本编译器 `sub_410D70`（按命令字符写 `*v118++ = 长度/命令/参数`） |
| 长度含自身 | 编译器写入 `*v3 = (_BYTE)v118 - (_BYTE)v3`，即整条记录长度 |
| `0x00` 结束 | 解释器 `sub_40F3F8`：`mov al,[edx]; test eax,eax; jz ...` 后调用结束处理 |
| 文本为 CP932 | 全样本 `TEXT` 负载按 CP932 解码可读；不可还原字节用 `{{XX}}` |
| 无压缩/加密 | 加载器只 `FileSeek`+`ReadFile`；块熵 2.67–5.93 |

长度前缀的实测：100 个脚本从头解析到 `0x00`，全部记录长度合法且不越界；
尾部残留 ≤7 字节，作为 `.byte` 数据原样保留。

## 3. 指令集

`length` 为整条指令字节数，`operands` 长度 = `length - 2`。

| 命令 | 助记符 | 参数 | 说明 |
|---|---|---|---|
| 0x09 | `TEXT` | CP932 文本 + `00` | 正文/对白 |
| 0x21 | `LABEL` | u8 ×2 + 文本 + `00` | 章节/场景标签；前缀样本为 `00 00`、`00 40`、`21 40` |
| 0x23 | `CHAR` | char[4] + u16 ×3 | 角色定义（YUKI、JK_A…） |
| 0x24 | `ANGLE` | u16 ×2 + 3×C 字符串 | 多角度/多视点（マルチアングル） |
| 0x25 | `SPEAKER` | 文本 + `00` | 说话人名牌（【由希】） |
| 0x2E | `IF` | 子码见下 | 条件/控制 |
| 0x2F | `TITLE` | 文本 + `00` | 场景/分支标题 |
| 0x3A | `SCENE` | 文本 + `00` | 场景名（chapter1） |
| 0x3E | `ENDING` | 文本 + `00` | 结局标题 |
| 0x40 | `RET` | u8 | 段结束；样本中恒 0 |
| 0x43 | `CMD43` | u8 ×2 | 全样本仅 1 条，语义未确认 |
| 0x46 | `FLAG` | 操作符 + u16 | `F-` 清标志 / `F+` 置标志 |
| 0x47 | `BG` | u16 ×3 + C 字符串 | 背景/事件资源（bg_01、EV_01A_1） |
| 0x52 | `VAR` | 操作符 + u16 + u16 | `R=` 变量比较/赋值 |
| 0x57 | `SND` | 见下 | 音频 |

### 0x2E 子码

| 子码 | 反汇编写法 | 参数 |
|---|---|---|
| 0x01 + 0x46 | `IF_F <op>, <u16>` | 内嵌 `FLAG` 判断 |
| 0x01 + 0x52 | `IF_R <op>, <u16>, <u16>` | 内嵌 `VAR` 判断 |
| 0x05 / 0x06 | `IF_V <子码>, <u16>` | 带 u16 参数 |
| 其它（0x03/0x08/0x09/0x0A/0x63） | `IF_C <子码>` | 单字节码 |

### 0x57 子类型

- `SND 'M', n`：`M` + u16 音乐编号。
- `SND 'V', 'P'/'d', "se_xx", flag`：`V` + 子类型 + `00` + 资源名 + `00` + flag。
  样本中 flag 基本为 0，`se_26` 一处为 0x81，因此作为独立操作数保留。

## 4. 文本与编码

- 落盘 asm.txt 为 UTF-8；`--encoding` 只影响字符串的二进制编码。
- 反汇编默认 `cp932`，汇编默认按 asm 头部 `; encoding:`，无头部时 `gbk`
  （与用户指定 `--encoding gbk` 一致，便于中文注入）。
- 不可显示/不可还原的字节写作 `{{XX}}`；字面 `{` 写作 `\{`，`"` 写作 `\"`。
- 文本末尾 `0x00` 不写入 asm，汇编器自动补回。

## 5. 零突变验证

```
python disassembler.py MIBOUJIN.SCB_unpacked -o out_asm --encoding cp932
python assembler.py out_asm -o out_bin --encoding cp932
```

100 个脚本逐个比较 SHA-256：**100/100 一致**。

## 6. 未确认项

- `0x2E` 各子码在运行时的确切语义（等待/跳转/结束）未做动态调试确认，命名 `IF_*` 为
  基于内嵌 `F`/`R` 判断的推断。
- `0x40`、`0x43` 的语义只按参数形状命名，未在游戏中验证。
- `0x21` 首字节为 0x21 时多出的前缀字节含义未确认。
- 未做游戏内实测；静态零突变不等于运行时通过。
